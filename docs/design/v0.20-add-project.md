# v0.20 — Add Project from Anywhere

**Status:** design, not yet implemented
**Owner:** Avinash
**Reviewers:** Claude (plan-eng-review), Claude adversarial subagent (outside voice)

## Problem

`canopy init` today requires you to be inside the project's root directory. That breaks two real flows:

1. **Initialize an existing folder from elsewhere.** You're working in another shell tab, you remember you have a project at `~/code/foo` that isn't yet a canopy project, you want to add it without dropping what you're doing.
2. **Clone + init in one shot.** You see a repo on GitHub you want to onboard. Today: `git clone https://github.com/foo/bar` → `cd bar` → `canopy init`. Three commands, three context switches.

The framing shift: this isn't "init this folder" anymore. It's **"add a project to canopy."** The project's source might be a local folder or a git URL.

## Goals (v0.20)

1. `canopy init [PATH_OR_URL] [DEST]` — single subcommand, auto-detects path vs URL. Backwards compatible (no args = today's cwd behavior).
2. Clones land in a configurable `source-root` (default `~/.canopy/sources`).
3. New `canopy config set|get|list|unset` subcommand for persistent user prefs. JSON file at `~/.canopy/config.json`, flock-protected.
4. TUI gains an "Add Project" form on the splash screen (replaces the single-key `i` shortcut) and on the Global tab (new `a` keybind). Both forms share the orchestrator with the CLI.
5. Clones from the TUI use `tea.ExecProcess` so SSH passphrases and HTTPS credential prompts work naturally.

## Non-goals (deferred to follow-ups)

- Workspace creation. `canopy new` is still a separate step after init.
- `--branch <name>` flag for clone. Users can `cd` in afterward.
- Auth handling in canopy code. Delegated to git (SSH agent, credential helpers, host-key prompts).
- Partial-clone cleanup on cancel. Leave the partial dir; document.
- Remote-host clone (v0.17 "remote workspaces" mean workspaces on another machine — separate concept; this feature is local-side onboarding).
- TUI deletion of registered projects.

## Locked-in decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Auto-detect URL via strict whitelist: `net/url.Parse` with scheme in `{http, https, git, ssh, file}`, OR regex `^[A-Za-z0-9_.-]+@[A-Za-z0-9.-]+:.+` for SSH-style. | Zero false positives. Matches `gh repo clone` / `cargo install` / `pip install` UX. |
| 2 | Source-root configurable. Precedence: CLI `<dest>` positional > `$CANOPY_SOURCE_ROOT` env > `~/.canopy/config.json` `source-root` > default `~/.canopy/sources`. | Most-specific-wins precedence, mirrors `git config`. |
| 3 | New `canopy config` subcommand (set/get/list/unset). JSON at `~/.canopy/config.json`, flock-protected (mirrors `state.Store.WithLock`). | Future-proof: room to add more user prefs later. |
| 4 | Lazy `MkdirAll` for source-root: created just before clone, not at `config set` time. | `config set` should not mutate the filesystem. |
| 5 | Re-run safety: if dest exists with `.git`, skip clone and init in place (idempotent). If dest exists without `.git`, error with collision message. | Idempotent CLI per canopy convention. |
| 6 | Pre-clone basename collision check. Derive basename from URL pre-clone, check state for collision, fail fast before any network/disk work. (Added per outside voice; the original plan checked post-clone, which would leave stranded dirs.) | Catch collision before downloading MB-GB. |
| 7 | Source-root path safety: validate dest is not inside any known workspace path before cloning. | Prevent clones landing inside `~/.canopy/workspaces/.../sources/`, which reconcile would treat as garbage. |
| 8 | TUI clones via `tea.ExecProcess` (mirrors `update_host.go:281`'s ssh-copy-id pattern). No spinner, no busy mode, no ctx-cancel plumbing. Drops out of altscreen, hands tty to git, resumes on completion. | Spinner UI captures stdin; private repos with SSH passphrases or HTTPS credential prompts would hang silently. |
| 9 | Shared orchestrator `runAddProject(arg, destOverride, opts, stdout)` callable from both CLI (no active tea.Program) and TUI (inside an active tea.Program via tea.ExecProcess). | Single code path; CLI and TUI cannot drift. |
| 10 | Bug fix bundled in this PR: `init.go:113` early-return when canopy.json exists currently does NOT call `registerProject`. Verified bug — `internal/workspace/projectroot.go:104-109` explicitly handles "canopy.json found but not in state" as a real unregistered state. Fix: also register on early-return. | Cloning a repo that ships `canopy.json` (e.g. canopy itself) would otherwise leave it unregistered. |
| 11 | Splash retains "empty Enter = init cwd" muscle memory. Global tab disables empty Enter (inline error "type a path or URL"). | Splash has a meaningful cwd; Global tab does not. |
| 12 | `~/.canopy/config.json` ships with `"version": 1` field from day one. `Load()` warns if it reads a version higher than known. No migration logic yet (separate TODO). | Cheap forward-compat insurance; the cost of adding it later is much higher than the cost of carrying it now. |
| 13 | TUI form renders as modal overlay with `lipgloss.RoundedBorder`. List behind dimmed via `subtleStyle`. Identical layout on splash and Global tab. | Mirrors `addHostFormMode` (`view.go:336`) exactly. Same visual language users already know. |
| 14 | On successful add: 3-second toast `✓ Added <name> at <path>` replacing help legend, then form closes and list refreshes. | Confirmation + auto-dismiss balances feedback and flow. User sees the destination without having to dismiss manually. |
| 15 | Form errors render inline below input field in `errorStyle` (red 196 bold), replacing help legend. Cleared on next keystroke. Prefix with `✗ ` icon. | Errors are immediate, in-context, not modal. Icon prefix makes color-blind users + screen readers see the signal. |
| 16 | TUI altscreen handoff (`tea.ExecProcess` for git clone) shows pre-exec status line `Running git clone... (canopy will resume here when done)` for ~200ms before terminal flip. | Prevents "did canopy crash?" panic during the brief altscreen drop. |
| 17 | Settings shortcut is `ctrl+s` (not bare `s`) to avoid conflict with typing `s` into URL field (URLs contain `s`: `ssh://`, `https://`). Help legend: `enter: add · esc: cancel · ctrl+s: change source`. | Bare `s` is unusable as a modal key when the same context captures keystrokes for typing. |
| 18 | Settings UX = inline edit-in-place: ctrl+s replaces the source-root status line with an editable textinput pre-filled with current value. Enter saves config, Esc cancels. | Lightest implementation, no new sub-modal, reuses the existing textinput state. |
| 19 | Form copy (verbatim): prompt `Folder path or git URL:`; status `Source: <path>  (config|env|default)`; legend `enter: add · esc: cancel · ctrl+s: change source`. Long paths in status: truncate left with `…` ellipsis preserving basename. | Clean, short, matches canopy's terse copy style. Truncation preserves the dir name users recognize. |
| 20 | Error strings (verbatim): empty (Global) = `✗ Type a path or URL.`; URL malformed = `✗ Not a recognized URL or path: <input>`; path missing = `✗ No directory at <path>`; dest collision = `✗ <dest> exists and isn't a git repo.`; clone failed = `✗ git: <stderr first line>`; basename collision = `✗ Project '<name>' is already registered at <other-path>. Use a different destination, or edit ~/.canopy/state.json to remove the stale entry.` | Concrete, name affected values, sentence-case, period-terminated, suggest recovery paths where they exist. |
| 21 | CLI clone output ordering (verbatim): `Cloning <url> into <dest>...` → git's normal output (inherited stdout/stderr) → `Wrote <dest>/canopy.json` → `Registered project '<name>'.` → blank line → `Next steps:\n  Run \`canopy new <branch>\` from <dest> to create your first workspace.` | Tells the user where the project landed AND that they need to cd there (since they aren't there yet). |
| 22 | All Add Project rendering reuses `internal/ui/render.go` styles: `titleStyle` for modal title, `subtleStyle` for dimmed list, `errorStyle` for inline errors, `readyStyle` (green) for success toast, RoundedBorder for modal frame. No new styles introduced. | Single design system. Future style changes propagate uniformly. |

                │                                │

                                                 │

                                       PRE-CLONE COLLISION CHECK:

                                       → error if collision (no clone done)
                                                 │

### `canopy config` shape

```
canopy config set source-root ~/Work    # writes ~/.canopy/config.json
canopy config get source-root           # prints value + source
                                        #   source ∈ {env, config, default}
canopy config list                      # all keys + values + sources
canopy config unset source-root         # remove key; fall back to default
```

Precedence (highest wins):
1. CLI dest positional (`canopy init <url> <dest>`) — per-call override
2. `$CANOPY_SOURCE_ROOT` env var
3. `~/.canopy/config.json` `source-root` key
4. Default `~/.canopy/sources/`

### `internal/git.Clone` signature

```go
// Clone runs `git clone <url> <dest>` via exec.CommandContext.
// On context cancel, git receives SIGKILL (CommandContext default).
// Returns error with git's stderr embedded so auth failures and
// invalid-URL errors surface readably.
//
// Does NOT mkdir dest's parent — caller must ensureSourceRoot first.
// Does NOT handle auth interactively — caller delegates to tea.ExecProcess
// (TUI) or inherits stdin (CLI) so git's own credential helpers work.
func Clone(ctx context.Context, url, dest string) error
```

## What already exists (reuse, don't rebuild)

- `runInit(cwd, opts, stdout)` — already path-parametric. The only thing tying it to cwd is `initCmd`'s `os.Getwd()`. Threading a positional arg through is a 5-line change.
- `internal/state.Store.WithLock` — flock pattern to mirror in `UserConfig.Save`.
- `internal/state.FindBasenameCollision` — reuse for pre-clone collision check.
- `internal/ui/update_host.go addHostFormMode` — copy-rename for `addProjectFormMode`. Same textinput state, same handler shape, same `tea.ExecProcess` path (lines 281+).
- `cmd/canopy/init.go canonicalize()` — reuse for path normalization.
- `cmd/canopy/init.go guardBasenameCollision()` — keep as in-runInit check (closes TOCTOU even with the new pre-clone check).

## Test plan

Per CLAUDE.md test discipline: every new conditional branch needs a test. ~88 paths total. Coverage diagram in the engineering review surfaces every gap; condensed here:

**Unit tests (★★ baseline, ★★★ where it matters):**
- `looksLikeGitURL` table-driven: 13 cases (5 URL shapes, 5 non-URLs, 3 boundary)
- `deriveBasename`: github HTTPS, ssh-style, trailing slash, .git suffix, empty error
- `resolveCloneDest`: 4-level precedence matrix
- `validateDestNotInsideWorkspace`: inside-workspace error, outside-workspace ok
- `ensureSourceRoot`: exists, missing, perm-denied
- `UserConfig.Load/Save`: missing file, valid JSON, invalid JSON, concurrent writes (flock)
- `UserConfig.SourceRoot`: env, config, default, source attribution
- `runAddProject`: empty arg, path arg, URL arg, URL + dest, dest collision, dest with .git, dest non-git
- `runInit` regression: canopy.json exists + project not registered → registers (the bug fix)
- TUI: `submitAddProject` classification, form key routing, error rendering, splash empty-Enter → cwd, Global empty-Enter → error

**E2E tests (-tags=e2e):**
- Hermetic clone: `t.TempDir()` + `git init --bare` + `file://...` URL, then `canopy init <url>` and assert state row created, canopy.json written.
- `canopy init <url> <dest>` with explicit dest override.
- `canopy config set/get/list/unset` round-trip.
- Splash → addproject via tea.ExecProcess (test harness uses `tmux -L canopy-test` socket per CLAUDE.md).
- Global tab `a` keybind opens form.

**Regression tests (FIRST, then code):**
1. `runInit` registers when canopy.json exists but project not in state (the bug fix).
2. Splash Enter on empty input still inits cwd (preserves muscle memory).
3. `canopy init` with no args is identical to today (no regressions for existing users).

## NOT in scope

- **Workspace creation:** `canopy new` remains a separate step after `canopy init`. The user explicitly clarified this scope mid-review.
- **--branch flag for clone:** users can `cd` in and check out a branch.
- **Auth handling in canopy code:** delegated to git (SSH agent, credential helpers).
- **Partial-clone cleanup on cancel:** leave the partial dir; document in `canopy init --help`.
- **Remote-host clone (v0.17 "remote workspaces" sense):** that's workspaces on another machine. This feature is local-side onboarding.
- **TUI project deletion:** `canopy rm` is for workspaces. Project removal stays manual (edit state.json) for now.
- **Multiple config keys beyond source-root:** the `canopy config` subcommand is built generically so future keys land easily, but v0.20 only ships `source-root`.

## Open risks

- **Mac/Linux only.** No Windows support assumed (canopy is already Unix-only via tmux). URL detection regex doesn't need to handle `C:\path` because canopy doesn't run there.
- **`tea.ExecProcess` portability across terminals.** The pattern works in existing `update_host.go` (ssh-copy-id), so we're inheriting tested behavior. New terminals are not exercised by canopy's CI today; assume parity.
- **Splash UX change.** Existing users who hit `i` daily will need to learn the new flow (type Enter for cwd). Worth a CHANGELOG note and a brief visible hint on the splash itself.

## Implementation order

1. **Phase A (no user-visible change):** Add `internal/config/userconfig` + `cmd/canopy/config` subcommand. Land alone for early feedback on the config UX. Tests on `Load/Save/SourceRoot/flock`. CHANGELOG: "New `canopy config` subcommand."
2. **Phase B:** Add `internal/git/Clone` + `cmd/canopy/init_source.go` helpers + `cmd/canopy/addproject.go` orchestrator. Extend `initCmd` to accept positional args. Bug fix in `runInit`. CLI flow complete. CHANGELOG: "`canopy init` now accepts a path or git URL."
3. **Phase C:** TUI form (`addProjectFormMode`), Global tab `a` keybind. Splash rewrite + `route.go` handoff. CHANGELOG: "Add Project in-TUI."

Each phase ships behind no flag — phases A and B are CLI-only and additive. Phase C is the UX change.
