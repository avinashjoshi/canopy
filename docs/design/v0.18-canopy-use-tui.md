# v0.18 — TUI picker for `canopy use`

Status: PLAN (draft)
Branch: `canopy-use-tui`
Supersedes: nothing — incremental UX on top of the v0.12.3 list view

## The change in one paragraph

`canopy use` (no args) on an interactive terminal currently prints a
four-column tabular list and exits. Users then re-run `canopy use
<name>` to actually flip. We collapse that two-step into one: when
stdin is a TTY and no target is given, launch a single-screen
Bubbletea picker that shows the same rows, highlights the active
target, lets the user pick with arrow keys + Enter, and falls through
to the existing `switchToRelease` / `switchToWorkspace` flows. When
stdin is not a TTY (pipes, scripts, CI), behavior is unchanged —
tabular output. A `--list` flag opts out of the picker even on a TTY.

This is a one-day diff: ~250 lines of new TUI code, ~30 lines of
wiring in `cmd/canopy/use.go`, ~400 lines of tests. No new packages.
No changes to the switch logic, the state model, or the symlink
machinery.

### Search check

- **bubbletea has `bubbles/list.Model` built-in.** Searched: "bubbletea list selector best practice 2026" — yes, `bubbles/list` is
  the standard component for selectable lists with filtering and
  pagination. **[Layer 1]**
- **But** canopy's existing TUI surfaces (InitSplashModel, the

  InitSplashModel explicitly cites consistency as the reason: "Every

  the alternate screen fully restores, output can land in the wrong
  buffer on some terminals. **Mitigation:** the InitSplashModel
  precedent already handles this — return from `Run` cleanly, then
  the caller writes its "Active: …" line to a normal stdout. We
  copy that pattern.

### Why the picker doesn't call switch funcs directly

Three reasons, in priority order:
1. **Altscreen hygiene.** Build output ("Building canopy in
   ~/.canopy/workspaces/canopy/foo …") needs a normal terminal.
   Switching inside the Bubbletea loop would either swallow that
   output or require risky temporary altscreen-exit dancing.
2. **Error surface symmetry.** `switchToWorkspace` returns errors
   that flow through cobra's `RunE` → exit code path. If the picker
   called it, the model would need to capture and re-render errors.
3. **Pre-existing precedent.** InitSplashModel does exactly this
   (set didInit, Quit, caller runs init). Following the established
   pattern means one less unique pattern to maintain.

### useRows() data shape

```go
// UseRow is one selectable target. Lives in cmd/canopy or in a tiny
// new internal package — see "Where does UseRow live?" below.
type UseRow struct {
    Target  string // "release" or workspace name
    Branch  string // "—" for release or when branch == name
    Version string // "v0.17.5.0", "DEV", or "—"
    Built   string // "built 2h ago" / "(not built)"
    Path    string // dev binary path; release_target for release row
    Active  bool   // matches current symlink target
    Built_  bool   // is the binary file present on disk
}
```

(Field name `Built` collides with `Built_` — pick `Buildable` or
`HasBinary` for the bool. Cosmetic, decide at write time.)

### Where does `UseRow` live?

Three options:

- **A) `cmd/canopy/use.go`** — package-private to the CLI. Picker
  imports it via `cmd/canopy` (it can't — `internal/ui` can't
  depend on `cmd`, that violates the leaf-up rule in CLAUDE.md).
  **REJECTED.**
- **B) `internal/ui`** — picker defines it; CLI imports `ui.UseRow`
  and constructs them. Adds an `internal/ui` dependency from
  `cmd/canopy/use.go`, which is already there (the CLI imports
  `ui.RunInitSplash`). **OK.**
- **C) New `internal/usepicker` package** — separation of "row
  data" from "rendering." Pure overkill for one type and one
  rendering surface. **REJECTED — would trip the "premature
  abstraction" wire in CLAUDE.md.**

**Recommendation: B.** Define `UseRow` in `internal/ui/use_picker.go`,
exported. CLI builds the slice, hands it to `RunUsePicker(rows)`,
also passes it to its own tabwriter renderer.

### One realistic production failure scenario per new codepath

1. **Picker:** terminal is too narrow (< 30 cols). Lipgloss wraps
   the row, the cursor caret moves but visually doesn't, user
   thinks the picker is frozen and force-quits the shell. **Mitigation:**
   on `tea.WindowSizeMsg`, if `Width < 40`, render a single-line
   "Terminal too narrow — try `canopy use --list`" hint instead of
   the rows. Tested.
2. **TTY detection misfires under tmux popup:** `canopy use` invoked
   from a tmux popup has stdin as a tty (popup is a real pty) but
   the popup auto-closes on exit, swallowing the picker. **Mitigation:**
   `enforceNoNestedTmux` already refuses many tmux-internal calls;
   this command has `allow-in-tmux=true` for the CLI surface. The
   picker works correctly in a tmux popup — verified by manually
   running the existing InitSplashModel from a popup. No code needed.
3. **State.json mutated mid-picker:** another canopy process removes
   a workspace while the picker is open. User selects the now-stale
   row, the switch fails on stat. **Mitigation:** existing
   `switchToWorkspace` returns a clear error ("no dev binary at …").
   The picker passes the target string through; the existing error
   path handles the race. No new code.
4. **`releaseVersionLabel` exec hangs near 2s** when the picker
   builds rows: the picker blocks before first paint, looking like
   it's frozen. **Mitigation:** the existing 2s timeout caps it.
   Worst case is a 2-second startup delay for the picker — same as
   the CLI's first-paint delay today. Could be improved with async
   loading and a spinner, but defer that — see TODOs.

## Code quality

### Tabwriter list and picker should share `useRows()`

Today, `printUseList` inlines row construction inside the rendering
loop. After the change, both renderers (tabwriter for CLI, lipgloss
for TUI) call `useRows()` and format the same data. DRY win.
Marginal complexity cost: one new function. Worth it.

### `chosenTarget` + `chosenBuild` is two flags

The picker exits with `(target string, build bool)`. We could
collapse to one `Choice` struct, but two return values matches
`RunInitSplash`'s `(didInit, err)` pattern and is dead-simple.
Keeping two flags.

### Error handling

`RunUsePicker` returns `(target string, withBuild bool, err error)`.
`err` is only non-nil on Bubbletea program failure (rare — terminal
detection issue, signal). Caller bails on err. Target == "" means
the user cancelled — caller exits 0 silently (no "cancelled" line,
matching how Esc on the main TUI works).

### Style coherence

Reuse `titleStyle` and `subtleStyle` from `internal/ui/render.go`.
For the active-target marker, use a third style — but check whether
`branchStyle` or one of the lifecycle-status styles already gives
us the right tone. If not, add `useActiveStyle` to render.go (one
line). Don't fork a new palette.

### ASCII diagram in the source

The `use_picker.go` header comment includes the same data-flow
diagram as this design doc, abbreviated. Future readers learn the
picker→caller separation from the comment, not from this design doc
(which decays).

## TODOs to capture (proposed for TODOS.md)

The user can pick which to add. Each follows the project's TODO
format with context for future-you.

### 1. Async row loading with spinner

**What:** Background-load `releaseVersionLabel` and show a spinner
on the release row instead of blocking first paint up to 2s.
**Why:** Cold invocations sometimes feel laggy (the 2s exec
timeout). Async load drops time-to-first-paint to ~10ms.
**Pros:** Snappier UX on cold start. **Cons:** ~80 lines of
plumbing for a ~5% case. **Context:** Today `printUseList` and the
new picker both block on `releaseVersionLabel`'s 2s exec timeout
when the cache is cold. The picker amplifies the perception
because users sit looking at a blank altscreen. **Depends on:**
this v0.18 plan landing first.

### 2. Picker `/` filter for >20 workspaces

**What:** If `len(rows) > 20`, enable a `/` filter input that
narrows by substring. **Why:** Avi's machine has 8-15 workspaces
typically; not urgent. Other power users may hit the limit.
**Pros:** Scales the picker past the casual cap.
**Cons:** Pulls us toward `bubbles/list`. **Context:** v0.18
explicitly hand-rolls because the picker is small. If telemetry
or user feedback shows workspace counts climbing, revisit.

### 3. Picker preview pane

**What:** Right-hand pane showing recent commit, branch ahead/
behind, last-modified file in the selected workspace. **Why:**
Helps users disambiguate similarly-named workspaces.
**Pros:** Stronger "I know which one I want" signal.
**Cons:** Doubles the picker's surface. Requires git plumbing.
**Context:** The host wizard's two-pane layout
(`cmd/canopy/host_wizard.go`) is a precedent if we go this way.

## Worktree parallelization strategy

This is a single-module change (`internal/ui` + `cmd/canopy/use.go`
