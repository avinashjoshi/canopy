## Problem statement

Today every canopy workspace lives on the laptop that created it. v0.16.1 shipped fire-and-forget agent workspaces (`canopy new --prompt`), but laptops have a hard ceiling on parallel agents: thermal envelope, battery drain, swap pressure. Worse, the laptop has to stay awake for the agent to keep working. Walk away, agents stop.

The narrow goal: let canopy workspaces live on other machines (BYO Linux box: home server, Fly Machine, EC2, omarchy laptop on tailscale) and let the laptop dispatch + attach as a thin client. Multi-agent fire-and-forget moves off the laptop entirely.

## What makes this cool

You wake up. You run `canopy` on your laptop. The Inbox tab shows three rows: `oauth-fix ✋ awaiting`, `perf-tune ⚡ thinking 2h`, `add-billing 💤 idle 15m`. The first one is stuck on a question; you press `c`, mosh-attach into tower, answer, suspend laptop, walk away. Your phone buzzes 40 minutes later — `perf-tune` finished. You attach from your phone via tailscale + tmux-in-browser (later phase), check the diff, approve. The agents kept working through all of it; your laptop ran for 2 minutes total.

The Sun ray analogy is load-bearing: the laptop is the screen, the remote canopy is the computer. The host abstraction makes them peers — every canopy is canonical for its own workspaces; the laptop's TUI aggregates across all peers.

This is the v0.17.x feature that reframes canopy from "workspace manager" to "dispatcher for a swarm of agents working in parallel."

## Constraints

- **First-time Go project discipline.** Stay grep-able, stdlib-shaped. SSH transport via `os/exec`. No fancy distributed-systems primitives.
- **No breaking changes for local-only users.** Existing `canopy new`, `canopy ls`, `canopy switch`, `canopy rm` keep working unchanged. Multi-host is purely additive — gated by `canopy host add`.
- **Linux-only on the remote.** canopy already targets Linux exclusively; the remote inherits that.
- **Tailscale-friendly.** No public IPs needed. MagicDNS hostnames work in `~/.canopy/hosts.json`.
- **Solo-dev workflow.** BYO box for v0.17. No multi-tenant SaaS. Managed `canopy.cloud` deliberately deferred (parked thesis in TODOS.md).

## Premises

1. **Each host is an independent canopy installation** with its own project registry, workspaces, credentials, and state.json. Hosts don't sync, don't mirror, don't share project definitions.
2. **Laptop is the thin client.** "Local" is just the canopy that happens to run on this same machine — same dispatch path, loopback transport. Not privileged, not special.
3. **Project registration is per host.** No cross-machine auto-clone. `canopy host project init <host>` is an explicit, deliberate action.
4. **No mode switching.** Hosts coexist as siblings in the Global tab. `--on <host>` is the CLI escape hatch; bare `canopy new` stays local for back-compat. The TUI's `n` opens the existing v0.16.2 picker, grown with one Host field.
5. **Picker can have a configured default host.** Default is fine because the picker is always visible — it can't become a hidden mode.

## Architecture

```
laptop                                   tower (or fly-iad, or omarchy-box)
─────────────────────────────────       ─────────────────────────────────
~/.canopy/hosts.json                    ~/.canopy/projects.json
~/.canopy/remotes-cache.json            ~/.canopy/state.json (canonical for tower)
~/.canopy/workspaces/<proj>/<ws>/       ~/.canopy/workspaces/<proj>/<ws>/
                                  ▲
                                  │ SSH (ControlMaster persistent multiplex)
                                  │   canopy ls --json
                                  │   canopy new <ws> --project <p> --prompt < stdin
                                  │   canopy rm <ws>
                                  │   canopy --version
                                  │
canopy TUI (Bubbletea)            │ canopy (CLI per request, no daemon)
  Project tab                     │
  Global tab    (sections by host)│
  Inbox tab     (sorted by state) │
  Hosts tab     (fleet view)      │
```

### Dispatch

The laptop's canopy holds the list of registered hosts. When dispatching (`canopy new`, `canopy ls`, etc.):

- For `local`, the existing code path runs unchanged.
- For remote hosts, `internal/host/ssh.go::Cmd(host, args...)` shells out to `ssh <ssh-target> canopy <args>` with ControlMaster flags. The remote canopy executes; output streams back.
- Per-host goroutines with 3s deadline on TUI refresh (one slow host can't freeze the TUI).
- ControlMaster sockets live in `~/.canopy/ssh-%C.sock`; stale sockets cleaned at startup.

### State ownership

Each host's `~/.canopy/state.json` is canonical for that host's workspaces. The laptop's `~/.canopy/remotes-cache.json` is a read-side aggregator for offline display and TUI rendering. Never writes back to remote state.json directly — only invokes remote canopy verbs that mutate it.

### Notifications

The laptop's polling loop watches the per-row state classifier output. On `* → StateAwaitingInput` transition (with 5s debounce against flicker), shells out to `notify-send -a canopy -i dialog-question "✋ tower: oauth-fix is waiting"`. Universal `libnotify` API; works on mako/dunst/gnome-shell. Notification is informational only in v0.17.0 (Path 1); click-handler via `--action` deferred to v0.17.x (Path 2 TODO).

### Version drift

Remote canopy reports its version in `canopy ls --json` output. Laptop compares to local version on each refresh:
- Same version: clean.
- Minor diff: render warning pill in section header (`tower (v0.16.2 — yours: v0.18)`).
- Major diff: refuse dispatch, surface banner asking user to update one side.

## v0.17.x scope (Phase 0 / Phase 1)

### Phase 0 — Afternoon hack (validation)

Smallest version that proves the loop end-to-end:
- `internal/host/` package skeleton: `Cmd(target, args...)` runs SSH with ControlMaster flags. Hardcoded single target.
- `canopy new --on <ssh-target>` flag: laptop SSHes out, runs `canopy new` on remote, prints back.
- Manual attach: `mosh <ssh-target> -- tmux attach -t canopy/<project>/<ws>`.
- No cache, no UI grouping, no Inbox, no notifications. Just dispatch + attach over SSH.
- Goal: feel mosh+tmux+nvim+claude over tailscale latency for a real hour. If it feels good, proceed. If it feels like working through a straw, stop and rethink.

### Phase 1 — Production shape

- `~/.canopy/hosts.json` + `canopy host add/ls/rm` CLI verbs.
- `~/.canopy/remotes-cache.json` aggregator; per-host goroutine refresh with 3s deadline.
- Global tab grows section grouping by host.
- v0.16.2 picker grows a Host field (seeded from cursor context or configured default).
- `canopy host project init <host>` flow: prompts for git URL + target path on remote; SSHes out and registers.
- ControlMaster persistent multiplex on all SSH calls; stale-socket cleanup at canopy startup.
- Version drift detection + warning pill.
- Inbox tab: third TUI tab, sorted across all hosts by agent state. Friendly empty state ("All caught up. 🌱"). Secondary sort by recency of state transition.
- Hosts tab: third TUI tab. Operational fleet view. Columns: host, ssh target, version, project count, ws count, last seen, RTT estimate. Keymap: `n` add (wizard), `r` remove, `enter` drill to projects, `p` ping.
- Desktop notification bridge: fire `notify-send` on `→ awaiting-input` transitions with 5s debounce.

### Phase 2+ (out of v0.17.x scope, captured in TODOS.md)

- Notification click-handler (Path 2: `notify-send --action`).
- Mobile/phone notification transport (ntfy.sh / Pushover / signal-cli).
- Web/browser terminal attach (gotty + tailscale Funnel).
- `canopy.cloud` managed-tier (parked thesis).
- `--forward-agent` opt-in flag for SSH (security explored alternative).
- Tailscale-aware host auto-discovery.
- Codex/opencode parity on remote hosts (orthogonal axis, ships independently).

## Locked-in calls

From CEO review 2026-05-11:

| Question | Decision |
|----------|----------|
| TUI refresh isolation | Per-host goroutines with 3s deadline (not synchronous serial) |
| Git creds on remote host | Each host has its own creds (not ssh-agent forwarding); `--forward-agent` deferred |
| E2E test strategy | Localhost-as-remote, gated `-tags=e2e` |
| Inbox empty state + sort | Friendly "All caught up", secondary sort by state-transition recency |
| `--prompt` over SSH | Via stdin / temp file, not command-line args (prevents `ps aux` leakage) |
| `cmd/canopy/new.go` shape | Extract `dispatchToHost(host, ...)` so new.go just resolves + dispatches |
| Workspace removed remotely | Surface row-removal via toast on next refresh |

## Approaches considered (CEO review)

- **A: Independent canopies + laptop aggregator** (CHOSEN). Each host is its own canopy; laptop talks to them as a peer over SSH.
- **B: Centralized state, remote workers.** Laptop holds master state.json, remotes are stateless executors. *Rejected*: violates thin-client premise; introduces distributed-systems concerns this project doesn't need.
- **C: Pure SSH-multiplex (no cache).** Live SSH on every TUI refresh, no `remotes-cache.json`. *Used as Phase 0 shape*; Phase 1 adds the cache for offline-tolerant UX.

## Why this is the v0.17.x release

It rides on three v0.16.x foundations:
- **v0.16.0 pane-role contract** — remote workspaces get the same canonical layout addressing.
- **v0.16.1 background workspaces (`--prompt` + agent state badges)** — the state classifier feeds the Inbox sort and the notification trigger.
- **v0.16.2 new-from-prompt picker** — the picker grows one Host field; no rewrite.

Each release was teaspoon-sized. This is the next teaspoon, scaled up by an order of magnitude in product impact: the host abstraction unlocks canopy.cloud, mobile attach, multi-tenant — every long-term direction sits on top of it.

## Acceptance / definition of done

Phase 0: User runs `canopy host add tower <ssh-target>`, registers a project on tower, fires `canopy new oauth-fix --on tower --prompt "..."`, the workspace exists on tower with the agent kicked off. Local TUI shows it under a "tower" section header. `c` mosh-attaches. End-to-end loop closes.

Phase 1: Multiple hosts visible in Global tab simultaneously. Inbox tab works across hosts. Hosts tab usable for fleet management. Picker host field works. Notifications fire on state transitions. Offline hosts degrade gracefully. Daily-driver acceptable.

Stretch (v0.17.x ship-validation): User runs 4+ agent workspaces on tower simultaneously while laptop is in suspend. Wakes laptop, attaches one, handles its prompt, suspends laptop, walks away. Workflow that's impossible in v0.16.x.

## Design system (locked via /plan-design-review)

No DESIGN.md exists for canopy (P3 TODO). The lipgloss palette in `internal/ui/render.go` is the de facto system. v0.17 maps to it as follows:

```
Status / element            | lipgloss color | glyph (a11y)
─────────────────────────── │ ────────────── │ ─────────────
Host online                  | 46 (green)     | ●
Host offline                 | 241 (gray)     | ○
Host degraded (auth fail)    | 214 (amber)    | !
Host broken (unreachable)    | 196 (red)      | ✗
Host setting up              | 39 (blue)      | …
Default host annotation      | 99 (violet)    | (suffix · default)
Version drift (minor)        | 214 (amber)    | (pill: vX.Y — yours: vX.Z)
Version drift (major)        | 196 (red)      | (banner: incompatible)
Inbox state: awaiting        | 214 (amber)    | ✋
Inbox state: thinking        | 39 (blue)      | ⚡
Inbox state: idle            | 241 (gray)     | 💤
Inbox state: inactive        | 241 (gray)     | ·
Selection                    | 62 bg / 231 fg | (inverted)
Section header               | 99 (violet)    | —
Subtle / placeholder         | 241 (gray)     | —
```

Universal rule: **glyph alongside color, never color alone.** ~8% of users can't distinguish green from red; the glyph carries meaning when color doesn't.

Notification icon (mako/dunst libnotify icon name):
- `→ awaiting-input`: `dialog-question`
- Future state-changes: `dialog-information`

## Responsive layout (locked)

Hosts tab uses tiered column drop based on terminal width:

```
WIDTH        | VISIBLE COLUMNS
≥160 cols    | name, ssh target, version, projects, workspaces, last seen, RTT
120-159 cols | name, ssh target, version, projects, workspaces, last seen
100-119 cols | name, ssh target, version, workspaces
80-99 cols   | name, version, state-glyph
<80 cols     | name, state-glyph (state column with version overlaid as subtitle)
```

Always-visible: name, state glyph. Always-visible at ≥80 cols: version.

Global tab section headers respect a **badge budget of one annotation per host**: section header line shows host name + status pill + ONE annotation (version drift OR default marker, not both). Default marker fades to gray when host has a drift pill.

Inbox tab uses single-column row format (status glyph, workspace name, host name, recency) and is width-tolerant — narrower terminals just truncate the recency suffix first, then workspace name from the right.

## First-refresh UX (locked)

Remote host sections render their **section header immediately** on tab open, with a spinner badge per host (`[refreshing]` next to host name) until the first SSH refresh completes. Spinner clears the moment data lands. Reuses the existing setting_up spinner pattern from `internal/ui/agent_poll.go`.

Local section never spins (it's instant). Remote sections spin once per canopy session (cached afterward).

Attach handshake feedback: `cmd/canopy/switch.go` prints `subtleStyle.Render("Attaching to " + host + "...")` to the terminal before exec'ing mosh, so the user sees something while mosh handshakes (~0.5-2s on cold-start).

## Empty states (locked)

- **Inbox empty**: `All caught up. 🌱   (last activity: 2m ago)` — friendly, contextual, time-aware
- **Hosts tab empty**: `No hosts registered. Press n to add a remote box (or run \`canopy host add <name> <ssh-target>\` from terminal).` — affordance-clear, terminal-equivalent shown
- **Global per-host section empty**: `(no workspaces on tower yet)` — minimal, parenthetical
- **Picker host field with zero hosts**: `(no hosts registered — add one with canopy host add)`

## Out of scope (explicitly)

- macOS / Windows on either end. Linux-only inherited.
- Multi-tenant on a single remote host.
- Authentication beyond SSH key auth.
- Repo state sync from laptop (uncommitted work) to remote. v0.17 rule: commit + push first.
- Public-internet exposure of remote canopy. Tailscale-only; no port-forwarding semantics in v0.17.
